## One project, one thread of work

A project brings related notes together. Keep the scope small enough that its name tells someone what they will find inside: **Website refresh** is more useful than **Everything**.

Each project has an overview. Use it for a short description of the work and links to the notes people open most often.

## Give notes useful names

Name a note for the question it answers or the decision it records. A few examples:

- What we learned from the first prototype
- Navigation decisions
- Launch checklist

Pin the notes you reach for every day. Everything else stays in the project list, ordered by its most recent edit.

## Use labels sparingly

Labels connect notes across projects. Try a small set such as `research`, `decision`, and `meeting`. You can filter by a label without moving a note out of its project.

When a project is finished, archive it. Archived projects remain searchable, so the reasoning behind old work is still there when you need it.
