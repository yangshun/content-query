# ContentQuery v1 features

- MIT-licensed ESM package for Node.js 22.12 or later, with optional Vite 8 and Next.js 16 integrations. Published Vite declarations use the host's Vite types without requiring the Vite+ development toolchain.
- Standard Schema metadata/computed validation and output inference, with grouped contextual errors.
- Bundled Zod-backed content builders through `import { schema } from "content-query/schema"`, with chaining, primitive coercion, and provider-independent `schema.input`, `schema.output`, and `schema.infer` types. Consumers need no separate Zod installation; other Standard Schema validators remain supported, and deployed runtime JavaScript imports no validators.
- Computed context includes the collection registry key and optional, typed loader source metadata. Built-in file loaders supply project-relative paths and multi-record keys; source-only edits participate in preparation cache invalidation. Existing Astro loaders remain compatible without supplying the ContentQuery metadata extension.
- `content-query/computed` provides reusable `readingTime()`, `wordCount()`, and `excerpt()` computed definitions with Standard Schema result types. Captured-body defaults, typed async input selectors, Markdown/text/HTML extraction, configurable reading speed, Unicode-safe excerpt limits, and cancellation work during preparation; only results enter deployed query data.
- Build-only root `content-query.config.{ts,mts,cts,js,mjs,cjs}` discovery, ambiguity errors, and an exact custom-path override; generated typings and Vite client guards follow the selected config. Source acquisition stays in preparation, with source-independent deployed queries and rendering.
- Markdown, JSON, YAML, TOML, and native Astro-compatible named content loaders with matching built-in identities. Existing content loader packages can be passed directly to collections; no adapter API is required.
- Optional [`@content-query/mdx`](../packages/mdx/README.md) owns a local MDX loader, ordinary ESM compiler, Vite integration, assets, React islands, and full React document rendering. GFM, heading IDs, highlighting, remark/rehype hooks, all four hydration directives, browser-only imports, supported data serialization, lazy document URLs, shared widget entries, and disposal-safe scheduling stay outside core. One public virtual module, `content-query:mdx:server`, supplies server lookups and rendering with automatic asset resolution. MDX declarations and build intermediates live under `.content-query/mdx/`, sharing the existing generated directory. Host rerenders preserve widget state until the rendered HTML changes; article identity uses compact local revision keys. The [React Router SSR example](../examples/react-router-mdx/README.md) exercises both modes and client navigation in production Chromium tests without source content. A [Next.js architecture review](./MDX-ARCHITECTURE.md) preserves a separate native adapter path; Next MDX runtime support remains unverified.
- Format-neutral immutable build-session source snapshots and ready/error subscriptions are forwarded through `contentQuery().api`, reusing the existing preparation and watcher. Snapshots expose only an opaque revision and collection/ID/file-path identities; metadata queries do not compile MDX bodies.
- MDX package widgets resolve server/browser exports independently and share browser entries. Generated imports coexist with ordinary MDX, `?raw`, and `?url`; failed compilation retries and initial validation errors preserve development recovery and host refresh. Production CSS remains scoped to reachable documents, and the complete asset manifest is emitted only to server inputs. Stable island prefixes support repeatable HTML, with explicit namespaces for repeated document roots. SSR requires an absolute asset base.
- Loader stores, inherited schemas and dynamic schema factories, collection-schema precedence, parsed-data reuse, digests, session metadata, logger/config helpers, portable Markdown rendering, and transactional asynchronous watcher callbacks.
- SQL-ordered `content.select(...fields).from(collection)` fluent queries with native await, and Drizzle-style `content.query.posts.findMany()` / `findFirst()` relational queries over shared normalized plans. Typed `columns` inclusion/exclusion, nested `with`, default metadata selection, object/relation predicates, stable sorting, pagination, and counts share both backends.
- Revision-scoped lazy ID indexes for equality-constrained root queries in both runtime backends, avoiding repeated collection scans while preserving filtering, projection, pagination, count, and adjacency semantics.
- Single-record queries avoid redundant default sorting, and built-in glob acquisition bounds outstanding file reads to 64 while retaining deterministic snapshots and grouped diagnostics.
- Markdown folder `source` shorthand and explicit Markdown/JSON/YAML/TOML source objects alongside native loaders.
- Relational `adjacent` and fluent `selectAdjacent()` projections under `_adjacent`, default ID neighbors, independent filtered/ordered sibling scopes, and typed nested neighbor selection.
- Generated `CollectionKey`, `CollectionData`, and `Collections` aliases for physical and `content-query:server` entries.
- Browser-safe `content-query:client` update subscriptions with serialized router revalidation and full-reload fallback; Void preserves component state and scroll.
- Forward/inverse relationships, explicit reference ownership, authored arrays, nested selection, and per-parent pagination.
- Rich value/presence preservation through synchronous devalue encoding and detached results. Plain selections and rendered output are copied directly, without an encode/decode round trip.
- Explicit retained-body access, supplied HTML, built-in HTML/headings rendering, and eager/deferred Markdown policy.
- In-memory and generated backends using the same JavaScript query semantics. Vite defaults to in-memory preparation and bundled output; standalone runtime publication requires `backend: "generated"`. The CLI, standalone API, and Next.js adapter retain generated storage by default.
- Portable generated ESM indexes and lazy payloads, typed standalone `buildContent()` with `BuildContentOptions` from `content-query/build`, the CAC-based `content-query build` CLI with `--watch`, and optional Vite integration. The CLI provides help/version output without loading configuration, short aliases, and equals-form values while rejecting invalid or repeated build options. Build diagnostics use `operation: "build"`.
- [Void](../examples/void/README.md), [React Router](../examples/react-router/README.md), [TanStack Start](../examples/tanstack-start/README.md), [Next.js](../examples/next/README.md), [SvelteKit](../examples/sveltekit/README.md), and [Angular](../examples/angular/README.md) examples use native server loaders/functions and verify production rendering. Next.js uses `withContentQuery()` from `content-query/next` for managed watching and generated-module HMR; the Vite examples subscribe to content updates. Angular uses native `@angular/ssr`, Router resolvers, and server API routes, with CLI content watching triggering Angular rebuilds.
- One default `.content-query/` directory for generated runtime artifacts and Vite declarations; in-memory Vite emits only types, while standalone in-memory preparation writes no files.
- Next.js configuration evaluations from the detached telemetry helper do not prepare content or start watchers, preventing sessions from surviving application shutdown.
- Generated watch sessions prune obsolete collection modules from previous runs after their first successful publication, then retain this session's revisions. Next.js also prunes previous-run development runtime entries while preserving the new entry; one-shot builds prune superseded artifacts.
- Settled filesystem writes, ordered candidate updates, cancellation, atomic publication, pinned operations, failure recovery, and owned-resource cleanup.
- Configuration failures stay active until a successful reload and preparation; loader-owned watcher listeners are released on configuration reload and disposal.
- Explicit source watches cover declared inputs under ignored project directories and missing inputs, honor glob exclusions, and exclude generated output. Initially missing declared paths retain a metadata polling fallback that restores native subscriptions if an ancestor creation event is lost, without polling every file in a glob collection.
- Vite diagnostics preserve BigInts, supported value graphs, and Error cause details across isolated runtimes; initial validation errors recover without restarting.
- Vite client-import rejection and runtime server-only fallback guards.
- Large-collection preparation reuses Markdown parser rules and unchanged immutable artifacts, with bounded publication I/O. Vite ignores generated output, prepares production content only for server graphs, and packs payload sources into lazy modules targeting 128 KiB before bundling, including hosts with strict entry signatures.
- Compact metadata indexes and lazy payload batches use portable gzip decoding when compression saves at least ten percent, retaining the existing value codec. Vite development also batches payloads, and concurrent delivery shares one revision serialization. Payload imports and decompression stay lazy, shared per batch, and retryable.
- Separate collection, query, runtime, preparation, loader, artifact, and integration modules behind stable package entry points; colocated unit tests and separate integration fixtures.

Verification combines shared conformance tests, typed callsites, controlled watch/race tests, loader tests, the published Astro CSV loader, native schema/watcher contracts, real generated/CLI consumers, Vite bundles, and the migrated VoidPress app. SQLite and other [future extensions](./TODO.md#future-extensions) are intentionally outside v1.
